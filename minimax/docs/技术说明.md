# sddctx 技术说明

作者：FDE WorkMate

## 要解决的问题

软件持续演进时，规格、决策、代码和测试会一起变化。开发助手如果只拿到一段需求描述，容易按旧决策实现，或改坏原有行为。sddctx 根据一张任务卡，从工程资料中选出“该遵循的规格、该改的代码、该跑的测试”，并保存任务进度，让中断后的开发从原处继续。

## 架构

```
任务卡 task.md ──► sddctx context ──► 上下文（Markdown/JSON，逐条标注来源与行号）──► MiniMax ──► 修改业务代码
                    ▲        ▲                                                           │
        seekdb 资料库        PowerContext 状态 ◄── ingest / baseline / context / agent / verify 每步写入
   （规格/代码/测试、链接、导入批次）   （scope、work contract、步骤 Source、handoff、task outcome）
```

## seekdb：工程资料库

- 解析：规格按 `### <ID>` 拆为条目，读取 `状态`（active/superseded）、`关联`（反引号中的符号/路径）、`依据`、`取代` 等元数据；代码用 `ast` 拆为模块、类、函数、方法，记录行号与引用名；测试拆到函数，记录引用的规格编号与调用的符号。
- 存储：`sdd_items`（条目、行号、内容哈希、正文、检索文本，`search_text` 建 ngram FULLTEXT 索引）、`sdd_links`（条目到符号/规格编号的链接）、`sdd_imports`（每次导入批次和变化摘要）。
- 增量导入：按内容哈希判定新增、修改、删除；内容不变但行号移动的条目只更新位置，保证上下文行号始终与文件一致。

## 上下文选择规则（通用规则，不含样例特判）

1. 主规格：用任务“要改什么”做全文检索；取得分不低于最高分 50% 的 active 候选，排除被其它候选以“依据”引用的决策条目，剩余最高分者为主规格。
2. 约束规格：其它候选、主规格的依据、“必须保持”段落检索命中的条目、关联到待修改符号的条目，再沿规格编号引用做有限深度补全。
3. 已失效决策：命中或被引用的 superseded 条目单列，标明“不得遵循”及取代者。
4. 代码：主规格关联的函数/方法为待修改符号，类型和模块为参考；待修改符号内部调用的工程内符号一并作为参考。
5. 测试：引用主规格的测试为目标功能测试；调用待修改符号、引用约束规格或被“必须保持”命中的测试为回归测试。

每次查询的 SQL、参数、命中条目和耗时写入 `db_queries.jsonl`；`sddctx check` 逐条回读源文件核对内容与行号。

## PowerContext：任务状态

- 每个工程一个 scope（`sddctx:<工程名>`，幂等创建），任务开始时写 work contract。
- 每完成一步写一个 content Source（`sddctx.step.v1`：步骤、是否通过、摘要、证据、代码版本），并提交 handoff（已完成、待办、下一步动作、引用的 Source）。
- 读取时用 `continue_handoff` 取最新 handoff，再按 Source 还原各步骤记录；`sddctx run` 跳过已完成步骤，从第一个未完成步骤继续。
- 上下文中的状态段会比较当前工程摘要与验证时的摘要、当前规格哈希与上次上下文的规格哈希，指出哪些验证已不再适用。
- 全部通过后写 task outcome（observations 与 checks 引用各步骤 Source）。

## MiniMax：代码修改

- 接口：`POST {MINIMAX_BASE_URL}/chat/completions`，模型 `MiniMax-M2`，温度 0.2。
- 输入：系统规则 + 上下文 + 待修改文件全文；输出：每个修改文件一个 `<file path="...">` 完整内容段。
- 约束：只允许写业务代码文件，模型若输出测试或规格文件直接拒绝；`<think>` 段不写入记录。
- 校验：写回后立即运行功能与回归测试，失败则把测试日志回传重试，最多 2 次。
- 复现：请求、响应、diff 全部记录；`--replay` 可在没有 Key 时重放同一份修改。

## 验证结果（TASK-001）

修改前：目标功能测试 7/7 失败（`unexpected keyword argument 'statuses'`），回归 9/9 通过。修改后：功能 7/7、回归 9/9、全量 16/16 通过。规格更新后：重新导入只改动变化条目，上下文使用新版 REQ-ORD-004 并标记原验证需重做，重新验证通过。具体数字以 `records/runs/` 中的记录为准。

## 局限

- 规格解析依赖 `### <ID>` 标题与元数据约定；代码解析目前只支持 Python。
- 上下文选择使用全文检索与显式链接，没有使用向量检索；规格措辞与任务差异很大时需要在规格中补充 `关联`。
- PowerContext Server 只用于本机回环，未启用鉴权。
